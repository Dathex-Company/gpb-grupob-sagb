# 📇 Padrão Oficial de Numeração Documental — Central de Padrões

**Data:** 13-06-2026  
**Status:** 🟢 Oficial  
**Série:** 00.10  
**Trilha:** 00.xx — Governança, Padrões Gerais e Regras da Central  
**Owner:** Central de Padrões / Loze  
**Substitui:** Nenhum (padrão inaugural de numeração)

---

## 📌 Resumo executivo

Todo documento da Central de Padrões deve usar numeração padronizada `NN.NN` como prefixo, garantindo rastreabilidade, ordenação automática e identificação visual da trilha. Este documento define o formato oficial, as reservas de série e as regras obrigatórias.

---

## 🏗️ Formato oficial

```
NN.NN-[tipo-ou-fase]-[escopo]-[modulo-ou-sistema]-DD-MM-AAAA.md
```

### Campos

| Campo | Descrição | Exemplo |
|---|---|---|
| `NN.NN` | Número da série com 2 dígitos + sub-índice com 2 dígitos | `01.15`, `03.02`, `00.10` |
| `[tipo-ou-fase]` | Tipo documental ou fase da trilha | `plano`, `auditoria`, `relatorio`, `execucao`, `fechamento` |
| `[escopo]` | Escopo ou assunto principal | `document-hub-v1`, `dark-mode`, `r5-persistencia` |
| `[modulo-ou-sistema]` | Módulo, sistema ou contexto alvo | `central-padroes`, `taskzei`, `sagb` |
| `DD-MM-AAAA` | Data no formato dia-mês-ano | `13-06-2026` |

---

## 📏 Regras obrigatórias

| # | Regra | Exemplo correto | Exemplo errado |
|---|---|---|---|
| 1 | **minúsculas** sempre | `plano-document-hub-v1` | `Plano-Document-Hub-V1` |
| 2 | **kebab-case** como separador | `auditoria-dark-mode` | `auditoria_dark_mode` |
| 3 | **sem acento** ou cedilha | `padrao-numeracao` | `padrão-numeração` |
| 4 | **sem espaço** em branco | `central-padroes` | `central padroes` |
| 5 | **sem underline** (`_`) | `document-hub-v2` | `document_hub_v2` |
| 6 | **data no final** com hífens | `-13-06-2026.md` | `-v1.0-13-06-2026.md` |
| 7 | **extensão `.md`** | `plano-xyz-13-06-2026.md` | `plano-xyz-13-06-2026.txt` |
| 8 | **zero à esquerda** obrigatório | `01.05`, `00.10` | `1.5`, `0.10` |
| 9 | **data consistente** com o conteúdo | `13-06-2026` | `99-99-9999` |

## 🔢 Reservas de séries (NN.xx)

| Série | Trilha / Domínio | Descrição |
|---|---|---|
| **00.xx** | Governança, Padrões Gerais e Regras da Central | Padrões, regras, mapas, índices e decisões estruturais da própria Central |
| **01.xx** | Document Hub V1 | Planos, execuções, auditorias, relatórios e fechamento do Document Hub V1 |
| **02.xx** | Design System / UI visual da Central | Dark mode, UI/UX, refatorações visuais, componentes de tela |
| **03.xx** | Document Hub V2 | Editor de oficiais ativos, persistência, versionamento, LOZE-TRACE |
| **04.xx** | Visual Preferences global / Configurações | Temas, preferências visuais, configurações globais de UI |
| **05.xx** | Telas Avançadas / dna_loze | Telas avançadas, DNA Loze, interfaces complexas |
| **06.xx** | Núcleo Conversacional | Chat, agentes, orquestração, conversação, memória |
| **07.xx** | API SagB | Endpoints, integrações, shell scripts, testes de API |
| **08.xx a 97.xx** | Novas trilhas | Reserva para trilhas futuras. Alocar sob governança da Central |
| **98.xx** | Fontes brutas, legado e material original | Extrações, V1/V2 originais, protocolos fonte, documentos não processados |
| **99.xx** | Fechamento geral, curadoria final | Consolidações excepcionais, fechamentos de ciclo, mega-relatórios |

### Regras de alocação

1. Novas trilhas recebem o próximo `NN.xx` disponível (08, 09, 10...)
2. O sub-índice `.NN` é sequencial dentro da trilha, começando em `.00`
3. Saltos intencionais são permitidos (ex: `.00`, `.05`, `.10` para planos comparativos)
4. Números `98.xx` e `99.xx` são reservas permanentes — não alocar novas trilhas neles
5. Alocação de nova série requer atualização deste documento

## ⚠️ Exceções documentadas

| Exceção | Justificativa | Ação |
|---|---|---|
| Arquivos em `estrutura-de-documentos-oficiais/` | Padrão próprio `dm-XX`, `gov-pad-XXX`, `tec-pad-XXX` | Não renomear — sistema independente |
| Arquivos em `99-curadoria/` | Material fonte, legado preservado | Não renomear — arquivo histórico |
| Migrations Supabase (`supabase/migrations/`) | Padrão técnico `YYYYMMDDHHMMSS_nome.sql` | Não renomear — exigência do Supabase |
| Arquivos de sistema (`.ts`, `.tsx`, `.json`, `.css`) | Código-fonte | Não se aplica — somente `.md` documental |
