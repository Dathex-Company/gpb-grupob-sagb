## 5. Fluxo de edição/salvamento

**Status atual:** Edição de metadados de documents NÃO existe no front-end.
- `DocumentsPage.tsx` só cria documentos (formulário de registro), não edita os existentes
- `StandardsPage.tsx` tem CRUD completo (create, update, delete)
- Documentos Mestres (em `DocumentosMestresPage.tsx`) são somente leitura
- Não há Markdown viewer
- Não há editor Markdown

## 6. Pontos quebrados encontrados inicialmente

1. `react-router-dom` ausente nas dependências do projeto (já instalado agora)
2. Possível ausência de status `previsto` e `registro` no enum
3. Documentos Mestres estão como `standards` — mistura conceitual
4. Chat Pietro pode não mostrar status corretamente
5. Status normativos podem não ter labels traduzidos consistentemente
6. Sidebar não tem todas as 25 páginas mapeadas (verificar)

## 7. Refatorações seguras previstas

1. Adicionar status `previsto` e `registro` se ausentes no enum
2. Adicionar labels/tradução para status normativos
3. Adicionar botão de editar metadados nos Documentos Mestres
4. Corrigir imports quebrados se existirem
5. Garantir que filtros de status funcionem com novos status
6. Ajustar o `StatusBadge` para novos status

## 8. Riscos

| Risco | Probabilidade | Impacto | Mitigação |
|---|---|---|---|
| Quebrar build ao adicionar novos tipos | Média | Alto | Buildar ao final |
| Status `previsto` não existir no enum | Alta | Médio | Adicionar com segurança |
| Dados inconsistentes entre fallback e Supabase | Média | Alto | Apenas registrar, não alterar |
| Mudar algo que Rodrigues dependia | Baixa | Alto | Nada destrutivo |
